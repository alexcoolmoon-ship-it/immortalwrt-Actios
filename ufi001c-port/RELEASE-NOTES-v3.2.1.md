# UFI001C v3.2.1 Clean

Профиль возвращает штатный Podkop 0.7.24 вместо набора UFI-надстроек.
Официальный OpenWrt 25.12.5 и аппаратная поддержка UFI001C остаются на прежних
закреплённых версиях; это персональный порт, не официальный образ проекта OpenWrt.

Удалены из образа ufi-care с восстановлением всей сети, ufi-lte-health,
ufi-dns-health, Zapret, ufi-service-proxy, подмены APK/wget и пакетного менеджера LuCI,
UFI-изменения интерфейса Podkop, отдельный engine failsafe. Штатный procd
по-прежнему управляет самим sing-box; фоновой службы проверки DNS нет.

DNS: основной и bootstrap резолверы используют прямой TCP к 77.88.8.8:53.
Глобального detour через XHTTP нет: обрыв прокси не обрывает разрешение обычных
доменов через тот же транспорт. Ответ SERVFAIL или пустой ответ больше не считается
успешной DNS-проверкой. TCP/UDP DNS не ждёт синхронизации NTP при запуске Podkop.
DoH/DoT остаются доступными в штатном интерфейсе. Запросы TCP DNS не шифруются.
FakeIP, правила по спискам и кэш остаются штатными для Podkop.

Podkop и LuCI взяты из itdoginfo/podkop, tag 0.7.24,
commit da8bd40983aaab4d29614d38c8d6214d0a217e3e. Все 26 файлов и ровно 7 изменённых
файлов перечислены с хэшами в clean/podkop-upstream.json. Изменения касаются
фиксации версии/зависимости движка, TCP DNS, диагностики и ожидания NTP,
первого подключения dnsmasq и пропуска пустого шаблона секции.

Повторная проверка выявила два сценария первого запуска. Начальное
shutdown_correctly теперь равно 1: на первом старте dnsmasq действительно
переключается на 127.0.0.42. При последующих стартах его резервная конфигурация
не дублируется. Пустой шаблон main больше не мешает добавленной секции с другим
именем; секции Block/Exclusion продолжают обрабатываться. Эти сценарии проверяются
исполнением настоящих shell-функций и штатного генератора.

CHECK-LTE.cmd адаптирован к чистому профилю: служба ufi-lte-health ему не нужна,
LTE проверяется через ubus/ip, DNS — напрямую, локальный FakeIP — на обоих
резолверах с проверкой маркированного маршрута. Второй процесс движка ради
диагностики не запускается. Успешный локальный FakeIP не выдаётся за проверку
удалённого XHTTP-сервера.

XHTTP требует podkop-engine; оставлена уже проверенная в предыдущей сборке версия
1.13.21-r12, без перехода на другую ревизию транспорта. Ссылка пользователя и её
extra, header uplink, x-edge-data и chunk 4000 должны сохраняться без подмены.
Протокол и сервер пользователя прошивка не меняет.

Сверены подходы itdoginfo/podkop (штатный DNS/FakeIP) и
hkfuertes/msm8916-openwrt (базовая аппаратная поддержка/ModemManager).
Разметка и настройки другой платы из второго проекта не копировались.
Источники: https://github.com/itdoginfo/podkop/tree/0.7.24,
https://github.com/hkfuertes/msm8916-openwrt,
https://github.com/FiyeroT/podkop-engine,
https://sing-box.sagernet.org/configuration/dns/server/tcp/.

Установщик со стока сохраняет полный бэкап, проверяет точные профили 4/8 ГБ,
радио, индивидуальные NV и обратное чтение. Отладочные обходы этих проверок не добавлялись.

Аппаратная приёмка нового образа ещё не проведена. Этот профиль убирает прежние
надстройки и зависимость DNS от прокси; он не доказывает причину перезагрузок
по предыдущему неполному журналу и не исправляет удалённый XHTTP-сервер.
