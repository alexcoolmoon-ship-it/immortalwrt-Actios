Проверка DNS UFI001C v3.2.3

1. Подключитесь к Wi-Fi модема. Вставьте свою прокси-ссылку в Podkop,
   сохраните и примените. Cloudflare DoH через прокси включён по умолчанию.
   Начальный DNS Яндекса: UDP; TCP доступен в настройках при необходимости.
2. В Podkop → Настройки нажмите «Проверить Cloudflare».
3. Запустите CHECK-DNS.cmd и введите пароль root, когда SSH его запросит.
   Сначала проверяйте без видео, затем повторите во время проблемы под нагрузкой.
   До получения отчёта не перезагружайте модем.
4. Откроется новая папка Downloads с UFI-DNS.txt. SSH_EXIT=0 означает лишь
   завершение сбора: смотрите отдельные PASS/FAIL, UTC, BOOT_ID и ошибки CURL.

Проверка не меняет конфигурацию, не перезапускает службы, Wi-Fi или LTE и
не очищает FakeIP-кэш. В отчёте скрыты имена/адреса сервера прокси и его ключи.
Яндекс используется только для разрешения адреса прокси. Клиентские запросы
не переключаются на прямой Яндекс при отказе Cloudflare или прокси.

После чистой перепрошивки ключ SSH модема может измениться. Если Windows
показывает REMOTE HOST IDENTIFICATION HAS CHANGED, проверьте подключение к
своему модему и его адрес 192.168.1.1. Затем в CMD выполните:
ssh-keygen -R 192.168.1.1
Повторите CHECK-DNS.cmd и примите новый ключ своего модема.

Аппаратная проверка: сайты HTTPS, видео не менее 30 минут, DNS до/после
нагрузки и перезапуска питания. Во время непрерывной работы BOOT_ID не должен
меняться; после намеренного отключения питания он меняется штатно.
