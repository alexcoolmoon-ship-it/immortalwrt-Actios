# LTE: два воспроизводимых RF-триггера

Отчёты от 18 октября 2026 относятся к действующей **v3.1.5**, плате
thwc,ufi001c и радио **UFI001BC 20211121 / HW 10000** с её собственными NV.
Это не испытание новой v3.1.6 и не доказательство совместимости всех UFI001C.

| Диапазоны | Наблюдение | Политика кандидата |
|---|---|---|
| B1, B3 | Регистрация без нового RF-сбоя в отдельных тестах | Оставлены |
| B7 | Два одинаковых RF-assert `rflte_dm_tx.c:3124`, примерно через 33 с после включения B7 | Исключён |
| B20 | Два RF-assert `rflte_msm.c:820` при выборе B20; повтор с метками команды | Исключён |
| B5, B8, B38, B39, B40, B41 | Нет регистрации в месте теста, нового RF-assert не было | Оставлены; работа при регистрации не подтверждена |

Номер из старого сообщения `Cannot get device config 0, band 19` сам по себе
не использован для сопоставления. Основание исключений — отдельные выборы
B7 и B20 с повтором RF-сбоя.

## Новая установка кандидата v3.1.6

Задаются `allowedmode=4g`, `allowedbands=supported-lte`,
`excludedbands=eutran-7|eutran-20`. При каждом подключении netifd строит список
из сообщённых модемом LTE-диапазонов и убирает только два указанных.
В наблюдавшемся списке остаются **B1/B3/B5/B8/B38/B39/B40/B41**.
Режим 2G/3G не включается. Ошибки списка, неизвестные исключения или пустой
результат останавливают подключение; возврата к `any` нет.

Профиль выбран для поставляемого радио UFI001BC по результатам одного
экземпляра. Для другого сочетания платы/радио/NV нужна отдельная проверка;
установщик продолжает отклонять неизвестный заводской профиль.

## Уже установленная v3.1.5

Её netifd не понимает `supported-lte` и `excludedbands`. Комплект
**APPLY-LTE** использует явную маску B1/B3/B5/B8/B38/B39/B40/B41 после проверки
версии радио, поддерживаемого списка и установленного протокола. Сохраняет
прежний network локально, проверяет новый LTE-сеанс и две минуты наблюдает RF.
При сбое связи сохраняет резерв B1/B3; старый профиль с B7 автоматически не
возвращает. Переподключается только интерфейс modem.

Это применение маски, а не перебор частот. Шаблоны прокси, LAN/Wi-Fi,
APN, разделы eMMC и NV не меняются. Сохранённая секция modem не сбрасывается
первым запуском новой сборки: для её миграции служит этот же комплект.

## Оставшийся отказ после полного прогона

Все шесть запланированных результатов 1.6 сохранены. Итог
`RECOVERY_NOT_CONFIRMED` возник **после последнего B41**: LTE-маршрут уже был,
DNS на 127.0.0.42 ответил, загрузки GitHub/OpenWrt через прокси прошли, но
один запрос DNS через роутер не ответил, а свежий sing-box записал XHTTP
`504 Gateway Timeout`. Ранее проверка DoH после возврата LTE прошла.
Это перемежающийся отказ DNS/туннеля, не доказательство RF-сбоя B41.

APPLY-LTE требует три успешных подряд проверки DoH через прокси и DNS роутера,
потом служебные загрузки. При повторном отказе допускается один перезапуск
существующего валидного sing-box. Ошибка прокси не служит основанием выключать
ещё частоты, подменять DNS прямым или снова перезапускать радио.
Устранение HTTP 504 на удалённом XHTTP/CDN по этим данным не подтверждено.

Короткие тесты не сертифицируют скорость, handover, другие соты или суточную
устойчивость. До стабильного выпуска нужен прогон новой маски с передачей
данных, затем реальный тест собранного образа после перезагрузки.


## Обновление v3.2.0

Первый запуск новой установки использует явную маску
`eutran-1|eutran-3|eutran-5|eutran-8|eutran-38|eutran-39|eutran-40|eutran-41`.
Именно она сохранена после перезагрузки в свежем отчёте 18 октября: LTE, DoH
и DNS прошли 3/3. Это подтверждает текущую загрузку исследованного экземпляра,
не новую прошивку, другие платы или регистрацию на всех перечисленных частотах.
