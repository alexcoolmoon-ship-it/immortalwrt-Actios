# Проверка v3.2.3 Clean

CI проверяет полный набор регрессий установщика и сетевого кода, точные хэши
снимка Podkop и девяти изменённых файлов, LuCI-переключатель Cloudflare,
выбор UDP/TCP и реальную обработку результата кнопки.

Новые проверки запуска выполняют настоящий start_main: Cloudflare требует
подготовки часов даже при сохранённом dns_type=tcp. Обычные TCP/UDP без режима
Cloudflare не запускают этот запрос. Реальный timeout завершает изолированный
макет зависшего ntpd, игнорирующего TERM; запуск после этого продолжается.
Настоящие часы машины и сеть теста не меняются.

С фактическим ARM64 podkop-engine под QEMU проверяются оба транспорта
начального DNS: отдельный UDP-сервер без TCP-слушателя и отдельный TCP-сервер
без UDP-слушателя. В каждом случае Cloudflare DoH работает через локальный
SOCKS-туннель с проверкой TLS и сертификатом тестового сервера:

- 200 запросов в 10 потоках, начальный DNS получает только имя прокси;
- SERVFAIL и восстановление в том же процессе без прямого DNS fallback;
- настоящая кнопка Cloudflare: успех, отказ и восстановление;
- FakeIP, обратное отображение в домен и сохранение после рестарта движка.

Сохраняются тесты ручного TCP DNS: 1000 запросов в 16 потоках, недоступный
прокси, SERVFAIL и восстановление. Отдельно проверяются XHTTP/extra, кэш,
отказ неверной конфигурации до установки правил/DHCP и сбор диагностического
отчёта без изменения настроек и раскрытия прокси-данных.

После сборки обязательны проверка фактического ядра с policy routing,
ARM64 ELF для ip-full/timeout-coreutils, точные файлы rootfs, отсутствие
прежних recovery-служб и Windows runtime от точного коммита. CHECK-DNS.cmd
и его коллектор проверяются в конечном USB-архиве.

Локальные серверы/QEMU не проверяют доступность удалённого VLESS/XHTTP сервера
пользователя и радиочасть UFI001C. Аппаратная приёмка: загрузка, LTE/Wi-Fi,
HTTPS-сайты, 4K-видео не менее 30 минут, DNS до/во время/после нагрузки,
неизменный BOOT_ID при работе и отсутствие OOM/remoteproc/RF crash.
