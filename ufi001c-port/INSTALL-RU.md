# UFI001C — OpenWrt 25.12.5 v3.1.4 Services / stock installer 3.1.4-rc1

v3.1.4 включает загрузку пакетов LuCI/APK через прокси, Podkop 0.7.24,
исправление FakeIP и обновление списков без потери прежнего файла при сетевой ошибке.
XHTTP r12, маршрутизация IPv4 и исправления USB/DNS из 3.1.3 сохранены.
Полный образ собирается в Actions. Он остаётся кандидатом до проверки на модеме.

## Исправить уже установленную 3.1.2 или 3.1.3 без перепрошивки

В архиве **UFI001C-services-v3.1.4.zip**:

1. Распакуйте архив в отдельную папку на Windows. Сохраните/примените свои изменения
   в Podkop и закройте вкладку LuCI. Подключитесь к модему 192.168.1.1.
2. Запустите **APPLY.cmd**. Он сверяет исходные файлы, сохраняет резервную копию
   в `/root/ufi-services-backup.XXXXXX` и обновляет только указанные файлы служб.
   Ссылки и настройки Podkop сохраняются. Ядро, разделы eMMC и база APK не меняются.
   Неизвестные локальные изменения или другая модель вызывают остановку до записи.
3. Запустите **START-CHECK.cmd**. Он перезапустит Podkop, проверит DNS/маршрутизацию,
   GitHub и репозиторий OpenWrt через прокси, затем выполнит `apk update`.
   Это обновление индексов, а не установка/обновление всех пакетов.
4. Откройте LuCI с **Ctrl+F5**, затем **Система → Программное обеспечение**.
   Нажмите «Обновить списки» и установите один нужный небольшой пакет.
5. Для проверки обрывов запустите **WATCH.cmd** и пять минут поработайте в LuCI.
   Файл `ufi-watch.txt` покажет boot_id и изменения USB. Затем перезагрузите модем
   и повторите START-CHECK.

Результаты сохраняются рядом со скриптами: APPLY-result.txt и ufi-start-result.txt.
При успешной проверке включается автозапуск Podkop. Если прокси не работает,
загрузки пакетов остановятся с понятной ошибкой; прямого обходного скачивания нет.
Возврат файлов — **ROLLBACK.cmd**, после него перезапустите Podkop.

Версия базовой прошивки после live-правки остаётся прежней. Метка исправления —
`/etc/ufi001c-services-fix`; скрипты/интерфейс Podkop показывают 0.7.24, однако база
APK сохраняет установленную прежде версию. Две новые строки настроек могут быть
на английском до полной сборки. Для версии 3.1.1 нужен полный образ или прежний
переход на 3.1.2: этот live-пакет не выдаёт себя за обновление ядра.

   https://github.com/alexcoolmoon-ship-it/immortalwrt-Actios/blob/main/.github/workflows/openwrt25-ufi001c.yml
   нажмите карандаш и замените содержимое текстом одноимённого файла из комплекта.
3. Сохраните коммит. В Actions выберите **OpenWrt 25.12.5 UFI001C v3.1.4 Services**:
   https://github.com/alexcoolmoon-ship-it/immortalwrt-Actios/actions/workflows/openwrt25-ufi001c.yml
   Нажмите **Run workflow → main**. Нужен новый запуск, не Re-run старого коммита.
4. Оставьте флажок `Publish the checked USB ZIP to GitHub Releases` включённым.
   После **Success** откройте Releases:
   https://github.com/alexcoolmoon-ship-it/immortalwrt-Actios/releases
   Скачайте **UFI001C-OpenWrt-25.12.5-v3.1.4-USB.zip** из Assets. В нём уже есть
   образы, ACCESS.txt, отчёты проверок и установщик. «Source code» не подходит.
   Повторно упаковывать через MAKE-BUNDLE.cmd не нужно.
   Если публикация выключена, архив доступен в артефакте **UFI001C-v3.1.4-USB-Download**.
   Развёрнутый артефакт **UFI001C-OpenWrt-25.12.5-v3.1.4-Services** сохраняется отдельно
   вместе с APK этой сборки. Это тот же комплект образов, другой способ скачивания.

Сборка проверяет ARM64-движок через QEMU и фактический kernel .config.
Без XHTTP или IPv4 policy routing артефакт не публикуется.
Длительность полной компиляции заранее не гарантируется. Ранее v2 собирался
примерно 53 минуты; новая версия Go может увеличить время.

## 2. Обновить ваш уже работающий OpenWrt

`INSTALL.cmd` предназначен для стока и не применяется здесь. Для этого модема
остаётся проверенный установщик **2.1.0**. Он обновляет только rootfs и boot.
Настройки/установленные вами приложения в rootfs будут заменены новыми.
Пока старый модем работает и доступен по Wi-Fi, сохраните настройки Podkop
на компьютере в CMD:

```cmd
if not exist "%USERPROFILE%\UFI001C-backups" mkdir "%USERPROFILE%\UFI001C-backups"
scp -O root@192.168.1.1:/etc/config/podkop "%USERPROFILE%\UFI001C-backups\podkop-before-v3.1.4.conf"
```

Этот файл содержит вашу прокси-ссылку и остаётся локально на компьютере.
Он сохраняет настройки Podkop, но не заменяет полный бэкап устройства ниже.

Распакуйте НОВЫЙ архив и перенесите содержимое `UFI001C-USB` в `%USERPROFILE%\openwrt25-v3.1.4` так, чтобы внутри
сразу лежали `boot.img`, `system.img`, `SHA256SUMS` и `ufi-install.py`.
Подключите модем к USB с зажатой кнопкой для EDL, затем отпустите её.
В CMD выполните:

```cmd
cd /d "%USERPROFILE%\openwrt25-v3.1.4"
"%USERPROFILE%\edl\.venv\Scripts\python.exe" ufi-install.py backup --images "%USERPROFILE%\UFI001C-backups"
```

Дождитесь **BACKUP VERIFIED**. Бэкап теперь находится вне папки прошивки.
Нужны примерно 12 ГБ свободного места. Не удаляйте этот бэкап вместе с папкой
программы. Вставьте напечатанный полный путь к свежему `emmc.bin`:

```cmd
"%USERPROFILE%\edl\.venv\Scripts\python.exe" ufi-install.py update --backup "ПОЛНЫЙ_ПУТЬ_К_СВЕЖЕМУ_БЭКАПУ\emmc.bin"
```

Скрипт проверит образы, GPT и принадлежность бэкапа этому устройству, запишет
rootfs/boot и прочитает записанное обратно. После **UPDATE VERIFIED**
переподключите USB **без кнопки**. Пароль Wi-Fi — в новом `ACCESS.txt`.
Панель: http://192.168.1.1 . Установите свой пароль root.

Подключитесь к новой Wi-Fi-сети модема и восстановите Podkop:

```cmd
scp -O "%USERPROFILE%\UFI001C-backups\podkop-before-v3.1.4.conf" root@192.168.1.1:/tmp/podkop.saved
ssh root@192.168.1.1 "cp /tmp/podkop.saved /etc/config/podkop && chmod 600 /etc/config/podkop && /etc/init.d/podkop restart"
```

После восстановления настроек Podkop выберет прежнюю заполненную секцию.
Проверка DNS и включение автозапуска:

```cmd
ssh root@192.168.1.1 "sh /usr/lib/podkop/ufi_dns_tunnel.sh check && ufi-services-check --apk-update && /etc/init.d/podkop enable"
```

Затем выполните:

```cmd
ssh root@192.168.1.1 "sh /usr/lib/podkop/ufi_dns_tunnel.sh check"
curl.exe -4 --noproxy "*" -I --connect-timeout 10 --max-time 20 https://www.google.com/
```

Ожидаются `IPv4 Podkop routing: rule and local route installed`,
`DoH through proxy: PASS` и HTTP-ответ Google. Временный маршрут для всего
диапазона 198.18.0.0/15 в этой прошивке создавать не нужно.
После первой успешной проверки перезагрузите модем и повторите обе команды.
Это проверит восстановление LTE, Podkop и DNS после обычного включения.

Если после прошивки SSH сообщает `REMOTE HOST IDENTIFICATION HAS CHANGED`,
сначала убедитесь, что подключены именно к новой сети модема. Затем выполните
в CMD `ssh-keygen -R 192.168.1.1` и подключитесь повторно.

Если произошла остановка — сохраните сообщение, бэкап и папку verify.
Не дописывайте нули в образы и не меняйте SHA256SUMS: обработка выравнивания
и OpenWrt metadata уже исправлена. Стоковый RESTORE.cmd не принимает бэкапы
существующего OpenWrt; это разные сценарии восстановления.

## 3. Каждый следующий стоковый UFI001C

Распакуйте успешный **артефакт прошивки** и откройте **INSTALL.cmd**.
Он попросит подключить только один модем в EDL, прочитает всю eMMC, сохранит
бэкап в `%USERPROFILE%\UFI001C-backups`, проверит точный заводской профиль и
перед записью попросит ввести **UFI001C**. Затем перенесёт собственные NV,
установит OpenStick-разметку/загрузчик и прошивку, проверит запись чтением.
После успешной проверки переподключите модем без кнопки.

Новый образ нельзя загружать в заводскую веб-панель: совместимость с её
форматом обновления не подтверждена. Подробности — `README-STOCK-RU.md`.
На вашем ПК используется уже работающий EDL. На новом ПК один раз потребуются
Python/EDL и USB-драйвер; INSTALL.cmd не устанавливает драйвер автоматически.

Установщик 3.1.4-rc1 проверен программными тестами. Первый переход со стока на
втором физическом модеме ещё нужен. При другом профиле платы/радио он остановится
до записи. Корпус и название чипсета сами по себе не доказывают совместимость.

## 4. Podkop, XHTTP и DNS

В образ включены **Podkop 0.7.24 + podkop-engine 1.13.21-r12**, обычный sing-box
исключён. Дополнительный ручной XHTTP-патч после прошивки не нужен.
Это движок FiyeroT, на который ссылаются авторы Podkop, не официальный SagerNet.

На модеме:

```sh
sing-box version
```

Ожидаются `1.13.21-pdk-r12` и строка Features с `transport.xhttp,tools.decode-link`.
В новой прошивке до настройки личного прокси Podkop выключен, поэтому
недоступный прямой DoH не лишит новый модем обычного доступа в интернет.
Podkop → Секции: вставьте свою XHTTP-ссылку в готовую секцию или создайте новую
с любым допустимым именем. Нажмите **Сохранить и применить**, затем **Запустить Podkop**.
В Настройках поле «Прокси для защищённого DNS» — «Автоматически». Если заполненных
прокси-секций несколько, можно выбрать нужный явно. Пустые секции игнорируются.
Для DNS через туннель поддерживаются URL, одиночный JSON outbound, Selector и URLTest.
Группы могут содержать только прокси; прямые выходы, VPN, циклы и цепочки detour
отклоняются. Для каждого сервера группы применяется отдельный bootstrap-резолвер.

Через 15 секунд проверьте и включите автозапуск:

```cmd
ssh root@192.168.1.1 "sh /usr/lib/podkop/ufi_dns_tunnel.sh check && ufi-services-check --apk-update && /etc/init.d/podkop enable"
```

Предварительно устанавливать DNS-патч отдельной командой больше не требуется:
он уже встроен, а секция выбирается до генерации конфигурации sing-box.

Podkop → Диагностика: проверьте запуск движка и DNS. При ошибке:

```sh
logread -e podkop | tail -60
```

Для проверки состояния без раскрытия прокси-ссылки достаточно версии и журнала.
Сами ссылки содержат секреты: в публичный репозиторий их не загружайте.

До задания личной прокси-ссылки готового туннеля нет. После запуска DNS использует
DoH 1.1.1.1 через выбранную заполненную секцию. Bootstrap 77.88.8.8 используется для разрешения
адреса прокси; запросы к остальным сайтам идут к основному DNS внутри туннеля.
Полная проверка: `sh /usr/lib/podkop/ufi_dns_tunnel.sh check`.
Отдельная проверка маршрутов: `sh /usr/lib/podkop/ufi_policy_routing.sh check`.
Версия комплекта: `cat /etc/ufi001c-release`.
Автоматический DNS-fallback движка к
оператору и аварийное отключение Podkop при циклических падениях выключены.
При недоступном DoH/движке DNS может не работать до исправления. Приложения
со своим DNS/VPN и ручное отключение Podkop не покрываются этой настройкой.

## 5. Кнопка, возврат Wi-Fi и zapret

На работающем модеме сначала коротко нажмите кнопку и выполните:

```sh
ufi-care status
logread -e ufi-care
```

Нужны `Recovery snapshot: VERIFIED` и `Reset button released after ...s`.
Только после появления события кнопка считается проверенной на этом устройстве.

| Удержание на работающем модеме, затем отпускание | Действие |
|---|---|
| Менее 8 секунд | Запись события в журнал |
| 8–19 секунд | Возврат сохранённых сети/Wi-Fi/DHCP/firewall |
| От 20 секунд | Возврат сохранённых файлов /etc/config |

Это возврат настроек, не полное стирание: пароль root и пакеты сохраняются.
После стартовой паузы отсутствие AP в течение 120 секунд запускает возврат
сети. Драйвер wcn36xx здесь не поддерживает одновременный AP+STA; реализовано
восстановление доступа после неудачного подключения к домашнему Wi-Fi.
Перед намеренным STA-only нужен проверенный отдельный доступ через USB Ethernet.

Восстановление ufi-care отключает Podkop/zapret, чтобы вернуть сеть и доступ
к панели. После этого их следует включить и проверить заново.

Zapret 72.13 уже установлен с подходящими модулями ядра. Перехват выключен,
пока не подобрана стратегия именно для оператора. Для диагностики:

```sh
cd /opt/zapret
sh blockcheck.sh
```

Результат определяет NFQWS_OPT; затем настраиваются NFQWS_ENABLE и сервис.
Само наличие пакета не гарантирует обход. Не направляйте одни и те же домены
одновременно через Podkop и zapret без проверки получившихся правил.


## 6. Что означает проверка FakeIP

v3.1.4 отдельно проверяет три вещи: выдаёт ли sing-box адрес из `198.18.0.0/15`,
передаёт ли DNS модема этот ответ клиентам и существует ли маршрут для помеченного
IPv4-трафика. Адреса `198.19.*` входят в тот же диапазон.

Внешний тест `fakeip.podkop.fyi:8443` может быть недоступен независимо от этих
проверок. `connection refused` не считается доказательством исправности или
поломки FakeIP. В интерфейсе такой результат обозначается как неизвестный.
Локальные зелёные проверки сами по себе не доказывают прохождение всего трафика:
проверьте HTTPS с компьютера и повторите после перезагрузки.

Команда `uci set ...='dns_only'` лишь выбирает существующую секцию. Она не создаёт
в ней proxy URL и не проверяет доступность сервера. В новой версии выбор
автоматический, поэтому удаление или переименование секции не оставляет DNS
привязанным к несуществующему имени.

Если в журнале повторяется `INTERNAL_ERROR; received from peer`, это отдельный
сбой потока на стороне соединения. Проверяйте работу той же ссылки в другом
клиенте и журнал сервера; смена индикатора FakeIP не исправляет такой сбой.

## 7. Пакеты и служебные обращения через прокси

В настройках Podkop включена «Загрузка пакетов и служебных файлов через прокси».
Сначала сохраните рабочую прокси-секцию и запустите Podkop. Затем работают LuCI
и обычные `apk update` / `apk add ИМЯ_ПАКЕТА`. HTTPS и подписи пакетов проверяются.
Не выполняйте массовое `apk upgrade`: оно может заменить специальные сборки
Podkop/движка и не является способом обновления этой прошивки. Модули kmod должны
совпадать с ядром; установка чужого модуля не исправляется настройкой прокси.
Подробности и проверка — [SERVICES-RU.md](SERVICES-RU.md).

## 8. Отдельный репозиторий

Создайте пустой репозиторий в своём GitHub, например `UFI001C-OpenWrt`.
Распакуйте `source-full.zip` и загрузите его содержимое в корень. README.md уже
является страницей проекта; отдельный GitHub Pages не нужен. Обновите ссылки
с `immortalwrt-Actios` на имя нового репозитория в README и инструкциях.
Разрешите Actions и запустите workflow v3.1.4 Services. Он публикует выпуск именно
в репозитории запуска через `github.repository`. Подробности: GITHUB-RU.md.
