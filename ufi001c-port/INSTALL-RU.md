# Установка UFI001C v3.2.3 Clean

Нужен полный **UFI001C-OpenWrt-25.12.5-v3.2.3-USB.zip** из успешной сборки,
не архив исходников. Распакуйте целиком. ACCESS.txt содержит новый пароль Wi-Fi.

## Заводской модем

Запустите INSTALL.cmd и следуйте подсказкам: EDL с зажатой кнопкой,
полный бэкап, проверка совместимости, подтверждение UFI001C, обратное чтение.
Python и EDL включены. При необходимости один раз выполните DRIVER-HELP.cmd.
Подробности в README-STOCK-RU.md. Поддержаны только точные известные профили 4/8 ГБ.

## Уже установленный OpenWrt/OpenStick

INSTALL.cmd предназначен для стока. Для OpenWrt используйте проверенный
ufi-install.py из комплекта и прежнее рабочее Python/EDL окружение Windows.
Сохраните свою прокси-ссылку отдельно. Новый rootfs устанавливается начисто.

Пусть распакованный комплект расположен в %USERPROFILE%\openwrt25-v3.2.3.
Оставьте подключённым один модем и переведите его в EDL. В CMD выполните:

```cmd
cd /d "%USERPROFILE%\openwrt25-v3.2.3"
"%USERPROFILE%\edl\.venv\Scripts\python.exe" ufi-install.py backup --images "%USERPROFILE%\UFI001C-backups"
```

После BACKUP VERIFIED используйте напечатанный полный путь к свежему emmc.bin:

```cmd
"%USERPROFILE%\edl\.venv\Scripts\python.exe" ufi-install.py update --images . --backup "ПОЛНЫЙ_ПУТЬ_К_СВОЕМУ_EMMC.BIN"
```

Дождитесь UPDATE VERIFIED, переподключите без кнопки и подключитесь по ACCESS.txt.
Обновляются только rootfs и boot; индивидуальные NV и GPT сверяются с бэкапом.

## Настройка Podkop

Откройте http://192.168.1.1, задайте пароль root. В Podkop → Секции
введите свою ссылку, сохраните, включите и запустите Podkop.
В Podkop → Настройки по умолчанию включён «Cloudflare DoH через прокси»:
Яндекс 77.88.8.8 UDP используется только для имён прокси, Cloudflare 1.1.1.1 DoH
идёт через выбранную прокси-секцию. При автовыборе берётся настроенная dns_only
или первая настроенная прокси-секция. Сохраните и примените настройки, затем
нажмите «Проверить Cloudflare». Проверка работает с применённой конфигурацией.
При выключении режима возвращаются обычные ручные настройки DNS.
«Протокол начального DNS Яндекса» по умолчанию UDP, как в ранней схеме.
Если оператор пропускает только TCP, выберите TCP и сохраните/примените.
Диагностика проверяет выбранный протокол, а не всегда TCP.
Старый /etc/config/podkop целиком не восстанавливайте. Перенесите свою ссылку
и списки, сохранив параметры XHTTP/extra. Отдельный DNS-патч на v3.2.3 не нужен.
Профиль LTE остаётся B1/B3/B5/B8/B38/B39/B40/B41, без B7/B20.

Для первого теста запустите CHECK-DNS.cmd в распакованном USB-комплекте:
он сохраняет UFI-DNS.txt в новой папке Downloads, проверяет Яндекс UDP/TCP,
Cloudflare через прокси, локальный DNS и FakeIP, показывает UTC и boot_id.
SSH_EXIT=0 означает завершение сбора; результат сети смотрите по PASS/FAIL.
Если SSH сообщает о смене ключа после чистой перепрошивки, сначала убедитесь,
что подключены к своему модему; инструкция обновления ключа в DNS-README-RU.txt.

Проверьте сайты, видео и DNS после перезапуска питания и 30 минут нагрузки.
Номер новой сборки показывает cat /etc/ufi001c-release. boot_id в
/proc/sys/kernel/random/boot_id должен оставаться неизменным в течение теста.
Подробная область CI и аппаратной проверки описана в VALIDATION-v3.2.3.md.
