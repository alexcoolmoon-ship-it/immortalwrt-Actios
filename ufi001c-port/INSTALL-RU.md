# UFI001C — OpenWrt 25.12.5 v3.1.1 Routing / stock installer 3.0-rc1

Это исходники и установщик. Готовые boot.img/system.img появятся после новой
успешной сборки в GitHub Actions. Пользователь подтвердил работу LTE и XHTTP
на v3. В v3.1.1 исправлены параметры IPv4 policy routing в ядре и добавлен
ip-full. DNS через прокси сохраняется при восстановлении настроек Podkop.
Podkop прекращает запуск при неработающей policy routing до изменения DNS.
Его диагностика учитывает настройку DNS через прокси и проверяет реальный
DoH-ответ, вместо прямого соединения к заблокированному серверу DNS.
Полная v3.1.1 пока не собрана и не проверена на устройстве.
32 программных теста и make defconfig пройдены; подробности в VALIDATION-v3.1.1.md.

## 1. Собрать один раз

1. Из комплекта откройте `github-update`. Загрузите **его содержимое** в корень
   существующего репозитория с заменой файлов:
   https://github.com/alexcoolmoon-ship-it/immortalwrt-Actios/upload/main
   Должны обновиться `ufi001c-port` и `.github/workflows`. Саму папку
   `github-update` в репозитории создавать не нужно. Существующие файлы не удаляйте.
2. Если проводник скрывает `.github`, обновите workflow отдельно: откройте
   https://github.com/alexcoolmoon-ship-it/immortalwrt-Actios/blob/main/.github/workflows/openwrt25-ufi001c.yml
   нажмите карандаш и замените содержимое текстом одноимённого файла из комплекта.
3. Сохраните коммит. В Actions выберите **OpenWrt 25.12.5 UFI001C v3.1.1 Routing**:
   https://github.com/alexcoolmoon-ship-it/immortalwrt-Actios/actions/workflows/openwrt25-ufi001c.yml
   Нажмите **Run workflow → main**. Нужен новый запуск, не Re-run старого коммита.
4. После **Success** скачайте артефакт **UFI001C-OpenWrt-25.12.5-v3.1.1-Routing**.
   Архив содержит образы, ACCESS.txt, XHTTP-отчёт, APK этой сборки и установщик.

Сборка проверяет ARM64-движок через QEMU и фактический kernel .config.
Без XHTTP или IPv4 policy routing артефакт не публикуется.
Длительность полной компиляции заранее не гарантируется. Ранее v2 собирался
примерно 53 минуты; новая версия Go может увеличить время.

## 2. Обновить ваш уже работающий OpenWrt

`INSTALL.cmd` предназначен для стока и не применяется здесь. Для этого модема
остаётся проверенный установщик **2.1.0**. Он обновляет только rootfs и boot.
Настройки/установленные вами приложения в rootfs будут заменены новыми.
Пока старый модем работает и доступен по Wi-Fi, сохраните настройки Podkop
на компьютере в CMD:

```cmd
if not exist "%USERPROFILE%\UFI001C-backups" mkdir "%USERPROFILE%\UFI001C-backups"
scp -O root@192.168.1.1:/etc/config/podkop "%USERPROFILE%\UFI001C-backups\podkop-before-v3.1.1.conf"
```

Этот файл содержит вашу прокси-ссылку и остаётся локально на компьютере.
Он сохраняет настройки Podkop, но не заменяет полный бэкап устройства ниже.

Распакуйте НОВЫЙ артефакт в `%USERPROFILE%\openwrt25-v3.1.1` так, чтобы внутри
сразу лежали `boot.img`, `system.img`, `SHA256SUMS` и `ufi-install.py`.
Подключите модем к USB с зажатой кнопкой для EDL, затем отпустите её.
В CMD выполните:

```cmd
cd /d "%USERPROFILE%\openwrt25-v3.1.1"
"%USERPROFILE%\edl\.venv\Scripts\python.exe" ufi-install.py backup --images "%USERPROFILE%\UFI001C-backups"
```

Дождитесь **BACKUP VERIFIED**. Бэкап теперь находится вне папки прошивки.
Нужны примерно 12 ГБ свободного места. Не удаляйте этот бэкап вместе с папкой
программы. Вставьте напечатанный полный путь к свежему `emmc.bin`:

```cmd
"%USERPROFILE%\edl\.venv\Scripts\python.exe" ufi-install.py update --backup "ПОЛНЫЙ_ПУТЬ_К_СВЕЖЕМУ_БЭКАПУ\emmc.bin"
```

Скрипт проверит образы, GPT и принадлежность бэкапа этому устройству, запишет
rootfs/boot и прочитает записанное обратно. После **UPDATE VERIFIED**
переподключите USB **без кнопки**. Пароль Wi-Fi — в новом `ACCESS.txt`.
Панель: http://192.168.1.1 . Установите свой пароль root.

Подключитесь к новой Wi-Fi-сети модема и восстановите Podkop:

```cmd
scp -O "%USERPROFILE%\UFI001C-backups\podkop-before-v3.1.1.conf" root@192.168.1.1:/tmp/podkop.saved
ssh root@192.168.1.1 "cp /tmp/podkop.saved /etc/config/podkop && chmod 600 /etc/config/podkop && /etc/init.d/podkop restart"
```

Дождитесь запуска Podkop в панели. Закрепите DNS через вашу существующую
секцию `dns_only` и включите автозапуск после успешной проверки:

```cmd
ssh root@192.168.1.1 "sh /usr/lib/podkop/ufi_dns_tunnel.sh install dns_only && /etc/init.d/podkop enable"
```

Затем выполните:

```cmd
ssh root@192.168.1.1 "sh /usr/lib/podkop/ufi_dns_tunnel.sh check"
curl.exe -4 --noproxy "*" -I --connect-timeout 10 --max-time 20 https://www.google.com/
```

Ожидаются `IPv4 Podkop routing: rule and local route installed`,
`DoH through proxy: PASS` и HTTP-ответ Google. Временный маршрут для всего
диапазона 198.18.0.0/15 в этой прошивке создавать не нужно.
После первой успешной проверки перезагрузите модем и повторите обе команды.
Это проверит восстановление LTE, Podkop и DNS после обычного включения.

Если после прошивки SSH сообщает `REMOTE HOST IDENTIFICATION HAS CHANGED`,
сначала убедитесь, что подключены именно к новой сети модема. Затем выполните
в CMD `ssh-keygen -R 192.168.1.1` и подключитесь повторно.

Если произошла остановка — сохраните сообщение, бэкап и папку verify.
Не дописывайте нули в образы и не меняйте SHA256SUMS: обработка выравнивания
и OpenWrt metadata уже исправлена. Стоковый RESTORE.cmd не принимает бэкапы
существующего OpenWrt; это разные сценарии восстановления.

## 3. Каждый следующий стоковый UFI001C

Распакуйте успешный **артефакт прошивки** и откройте **INSTALL.cmd**.
Он попросит подключить только один модем в EDL, прочитает всю eMMC, сохранит
бэкап в `%USERPROFILE%\UFI001C-backups`, проверит точный заводской профиль и
перед записью попросит ввести **UFI001C**. Затем перенесёт собственные NV,
установит OpenStick-разметку/загрузчик и прошивку, проверит запись чтением.
После успешной проверки переподключите модем без кнопки.

Новый образ нельзя загружать в заводскую веб-панель: совместимость с её
форматом обновления не подтверждена. Подробности — `README-STOCK-RU.md`.
На вашем ПК используется уже работающий EDL. На новом ПК один раз потребуются
Python/EDL и USB-драйвер; INSTALL.cmd не устанавливает драйвер автоматически.

Установщик 3.0-rc1 проверен программными тестами. Первый переход со стока на
втором физическом модеме ещё нужен. При другом профиле платы/радио он остановится
до записи. Корпус и название чипсета сами по себе не доказывают совместимость.

## 4. Podkop, XHTTP и DNS

В образ включены **Podkop 0.7.23 + podkop-engine 1.13.21-r12**, обычный sing-box
исключён. Дополнительный ручной XHTTP-патч после прошивки не нужен.
Это движок FiyeroT, на который ссылаются авторы Podkop, не официальный SagerNet.

На модеме:

```sh
sing-box version
```

Ожидаются `1.13.21-pdk-r12` и строка Features с `transport.xhttp,tools.decode-link`.
В новой прошивке до настройки личного прокси Podkop выключен, поэтому
недоступный прямой DoH не лишит новый модем обычного доступа в интернет.
Podkop → Секции → `dns_only`: вставьте свою XHTTP-ссылку, сохраните и примените.
Нажмите «Запустить Podkop», если он ещё остановлен. DNS и загрузка списков
уже направлены через эту секцию. Затем проверьте туннель и включите автозапуск:

```cmd
ssh root@192.168.1.1 "sh /usr/lib/podkop/ufi_dns_tunnel.sh install dns_only && /etc/init.d/podkop enable"
```

При восстановлении сохранённого файла вашего нынешнего Podkop используется
ваша прежняя прокси-ссылка. Если создали секцию с другим именем,
подставьте это имя вместо `dns_only` в команде.
Проверка сначала испытывает существующий туннель, затем сохраняет резервную
копию настроек и включает DoH/загрузку списков через выбранный прокси.
Поддерживается одна обычная proxy-секция со ссылкой, не selector/urltest/VPN.

Podkop → Диагностика: проверьте запуск движка и DNS. При ошибке:

```sh
logread -e podkop | tail -60
```

Для проверки состояния без раскрытия прокси-ссылки достаточно версии и журнала.
Сами ссылки содержат секреты: в публичный репозиторий их не загружайте.

До задания личной прокси-ссылки готового туннеля нет. Команда выше включает
DoH 1.1.1.1 через вашу секцию. Bootstrap 77.88.8.8 используется для разрешения
адреса прокси; запросы к остальным сайтам идут к основному DNS внутри туннеля.
Полная проверка: `sh /usr/lib/podkop/ufi_dns_tunnel.sh check`.
Отдельная проверка маршрутов: `sh /usr/lib/podkop/ufi_policy_routing.sh check`.
Версия комплекта: `cat /etc/ufi001c-release`.
Автоматический DNS-fallback движка к
оператору и аварийное отключение Podkop при циклических падениях выключены.
При недоступном DoH/движке DNS может не работать до исправления. Приложения
со своим DNS/VPN и ручное отключение Podkop не покрываются этой настройкой.

## 5. Кнопка, возврат Wi-Fi и zapret

На работающем модеме сначала коротко нажмите кнопку и выполните:

```sh
ufi-care status
logread -e ufi-care
```

Нужны `Recovery snapshot: VERIFIED` и `Reset button released after ...s`.
Только после появления события кнопка считается проверенной на этом устройстве.

| Удержание на работающем модеме, затем отпускание | Действие |
|---|---|
| Менее 8 секунд | Запись события в журнал |
| 8–19 секунд | Возврат сохранённых сети/Wi-Fi/DHCP/firewall |
| От 20 секунд | Возврат сохранённых файлов /etc/config |

Это возврат настроек, не полное стирание: пароль root и пакеты сохраняются.
После стартовой паузы отсутствие AP в течение 120 секунд запускает возврат
сети. Драйвер wcn36xx здесь не поддерживает одновременный AP+STA; реализовано
восстановление доступа после неудачного подключения к домашнему Wi-Fi.
Перед намеренным STA-only нужен проверенный отдельный доступ через USB Ethernet.

Восстановление ufi-care отключает Podkop/zapret, чтобы вернуть сеть и доступ
к панели. После этого их следует включить и проверить заново.

Zapret 72.13 уже установлен с подходящими модулями ядра. Перехват выключен,
пока не подобрана стратегия именно для оператора. Для диагностики:

```sh
cd /opt/zapret
sh blockcheck.sh
```

Результат определяет NFQWS_OPT; затем настраиваются NFQWS_ENABLE и сервис.
Само наличие пакета не гарантирует обход. Не направляйте одни и те же домены
одновременно через Podkop и zapret без проверки получившихся правил.
