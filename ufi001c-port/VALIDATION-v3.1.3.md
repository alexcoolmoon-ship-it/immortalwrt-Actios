# Проверки v3.1.3 Stability

Локально выполнены тесты генератора Podkop, DNS, маршрутизации, USB-обработчика,
проверок образов/GPT, моделируемой записи/восстановления и live-установщика.
Конфигурации URL, Selector и URLTest проверены настоящим podkop-engine
1.13.21-r12 для x86_64 и AArch64; AArch64 запущен через QEMU без подключения
к внешним серверам. Проверка OpenWrt metadata использует настоящий fwtool.

Регрессии по новым изменениям:

1. USB=0 не вызывает перезапуск по умолчанию; явное включение ограничивает
   повторные и параллельные вызовы.
2. DNS использует группу, все её серверы получают bootstrap resolver.
   Циклы, прямые резервные выходы, дубликаты тегов и пустые группы отклоняются.
3. Полный генератор сохраняет XHTTP и согласует служебный прокси с DNS.
4. Точные профили 4/8 ГБ различаются; неизвестный размер и сдвиг раздела
   отклоняются. GPT для 4 ГБ размещается в конце соответствующего диска.
5. Несовпадение заводского радио продолжает блокировать прошивку.
6. STOCK-CHECK делает только чтения двух GPT и раздела радио, без NV.
7. Live-патч сохраняет прокси-настройки; неизвестный файл блокирует установку;
   ошибка записи настроек вызывает откат. Сетевые службы не используются
   тестами — все действия выполняются в изолированных макетах.

Проверки Actions для нового образа: тесты, сборка, флаги маршрутизации ядра,
содержимое rootfs, ARM64 XHTTP, размеры/хеши образов и единый USB-архив.
Они не считаются выполненными до успешного запуска workflow v3.1.3.

Ещё нужна аппаратная проверка: USB и Wi-Fi при работе с LuCI, изменение boot_id
при настоящем перезапуске, LTE, DoH через рабочий прокси, длительная нагрузка,
переход со стока на втором модеме и восстановление. В присланных before/after
снимках интервал всего 6 секунд и одинаковый boot_id; этого недостаточно для
вывода об отсутствии перезагрузок в остальное время.
