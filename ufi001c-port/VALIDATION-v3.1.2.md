Последний журнал владельца на v3.1.1 подтверждает запуск Podkop, правило

Ошибки HTTP/2 INTERNAL_ERROR received from peer остаются отдельным вопросом
соединения с удалённой стороной.

## Воспроизведение

Нужны Python 3, Node.js, jq, POSIX sh и собранный fwtool:

```sh
FWTOOL_TEST_BINARY=/absolute/path/to/fwtool python3 -m unittest discover -s ufi001c-port/tests -v
```

Для проверки настоящим engine задайте UFI_TEST_ENGINE: путь к sing-box или
команда с musl loader. Без этой переменной тест генератора использует mock decoder.
Без FWTOOL_TEST_BINARY один отдельный тест может быть пропущен.

## Обязательные проверки CI

После сборки проверяются фактические kernel .config, содержимое rootfs,
ARM64 XHTTP в QEMU, структура boot/system и SHA256. Упаковщик сверяет отчёт
rootfs с текущими исходниками и XHTTP-отчёт с хешами образов. Release помечается
Pre-release, пока аппаратная приёмка не подтверждена.

## Приёмка владельцем

1. На текущей v3.1.1: APPLY.cmd, Ctrl+F5 в Podkop, START-CHECK.cmd.
   Рабочую сохранённую ссылку вводить заново не нужно. Если секций нет,
   заполнить восстановленную секцию, сохранить и применить.
2. Ожидаются DoH through proxy: PASS, local_fakeip/dnsmasq_fakeip/policy_route=true,
   HTTP-ответ Google с ПК. Внешний тест может остаться недоступным.
3. Перезагрузить и повторить; проверить нужные сайты и фактическую скорость.
4. На новом образе проверить переход со стока с собственным бэкапом,
   LTE, Wi-Fi/LuCI, событие физической кнопки и восстановление сети.

Прохождение локальных тестов не означает отсутствие всех возможных ошибок.
