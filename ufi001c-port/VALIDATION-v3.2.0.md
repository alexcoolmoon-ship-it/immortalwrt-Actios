# Проверка v3.2.0

## Что подтверждено на действующем модеме

Отчёт 18 октября 2026: `CURRENT_BOOT_LTE_DNS_PROXY_OK`, совпадающий boot ID,
LTE-only маска B1/B3/B5/B8/B38/B39/B40/B41, LTE health 3/3, HTTP 200 DoH через
локальный прокси 3/3, локальный DNS 3/3. За окно примерно 14 секунд новых RF-событий
нет. Обезличенные данные: reports/hardware-postboot-20261018.json.
Это действующая установленная система, не образы v3.2.0.

Позднее пользователь сообщил о повторном отказе DNS после 4К-видео. На снимке
LTE link/address/default_route исправны и sing-box запущен, но внешние DNS-пробы
не проходят. Короткая успешная проверка выше не доказывает устойчивость под нагрузкой.
Без журнала отказа не установлено, был ли сбой вызван потерями UDP, зависшим
туннелем, исчерпанием ресурсов или внешним сервером. Изменения DNS в этом кандидате
проверены имитацией отказов; повторный тест 4К на реальном новом образе обязателен.

## Автоматические проверки

Python-тесты проверяют подготовку образов, разметки 4/8 ГБ, CRC, свои NV,
привязку бэкапа, отказ неизвестному радио, частичное чтение, возобновление,
проверку записи, kernel routing, DNS/FakeIP/XHTTP, fresh-report и runtime manifest.
Настоящие Firehose-записи в локальных тестах имитируются.

Локально 18 октября 2026 выполнено 192 теста: 191 прошёл, один пропущен
из-за отсутствия бинарника fwtool. Проверены синтаксис Python/shell и подготовка
закреплённых исходников EDL/31 MSM8916 loaders с проверкой хэшей.
Новые DNS-регрессии проверяют SERVFAIL с нулевым кодом dig, зависший внешний DNS
при рабочем кэше, раздельный перезапуск dnsmasq/sing-box, паузу/лимит попыток,
смену конфигурации, ручную остановку Podkop, отсутствие LTE и повреждённое состояние.
Windows job запуска 39137308559 успешно собрал оба EXE, проверил 31 закреплённый
loader и выполнил три проверки запуска переносимого runtime. Firmware job
остановился на тестовом предположении о root-пользователе Linux; тестовое
окружение исправлено без изменения проверки прав на самом модеме. Сборка новых
образов и аппаратная приёмка нового комплекта ещё предстоят.

Windows job проверяет блокировки NTFS, формирует переносимые EXE и запускает
их в отдельных процессах с каталогом с пробелами/кириллицей. Он проверяет импорты,
наличие loader database и доступность DLL/backend без USB. Это не испытание драйвера
на реальном устройстве и не прошивка модема.

Firmware job сохраняет обязательные проверки конфигурации, ядра, rootfs,
ARM64 sing-box/XHTTP под QEMU и привязку xhttp-validation.json к хэшам образов.
USB-ZIP собирается только с runtime того же коммита и исходников; изменённый
или неполный комплект отклоняется до упаковки.

## Аппаратная приёмка до стабильного релиза

1. Запустить полный USB-ZIP на поддержанном стоковом экземпляре с его собственным бэкапом.
2. Подтвердить первый запуск, LuCI/Wi-Fi/USB, LTE с его SIM, ввод своей прокси-ссылки.
3. Выполнить CHECK-LTE.cmd после загрузки, проверить передачу данных и работу под нагрузкой.
4. Проверить кнопку и согласованный сценарий восстановления; отдельно — возврат из Wi-Fi STA.
5. Проверить откат собственного экземпляра через RESTORE.cmd, не публикуя полный дамп/NV.

До этого новый выпуск — Final Candidate / Pre-release. Неизвестные заводские
разметки и радио по этому пакету не допускаются к записи.
