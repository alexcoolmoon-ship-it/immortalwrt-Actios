## Установка стокового модема

Нужен полный **UFI001C-OpenWrt-25.12.5-v3.2.0-USB.zip** из успешной сборки.
Это один ZIP: образы, Windows-программы, EDL, USB-библиотека, драйверный помощник
и инструкция. Python, Git и EDL на ПК устанавливать не требуется.

1. Распакуйте ZIP целиком и запустите **INSTALL.cmd**.
2. Подключите один модем к USB с зажатой кнопкой, затем отпустите её.
3. Дождитесь полного бэкапа и проверки совместимости. Введите `UFI001C` для записи.
4. После проверки записи переподключите модем без кнопки. Подключитесь к Wi-Fi
   из ACCESS.txt и откройте **http://192.168.1.1**.

На новом Windows-ПК при недоступном USB выполните **DRIVER-HELP.cmd** один раз:
он открывает Zadig и короткую инструкцию для WinUSB на **05C6:9008**.
Установщик не заменяет драйверы других устройств автоматически.

Бэкап каждого экземпляра сохраняется отдельно в `%USERPROFILE%\UFI001C-backups`.
При обрыве чтения есть RESUME.cmd; возврат к стоку — RESTORE.cmd и свой бэкап.
Скорость зависит от USB, eMMC и размера полного бэкапа; фиксированное время
«за несколько минут» не заявляется. Все записи проверяются обратным чтением.

Поддержаны только две точные заводские разметки eMMC 4/8 ГБ и известный хэш радио.
Другая ревизия останавливается до записи. Для уже установленного OpenWrt используйте
[инструкцию обновления](ufi001c-port/INSTALL-RU.md), а не конвертацию со стока.

## LTE и проверенное поведение

Первый запуск задаёт **только 4G** и явную маску **B1/B3/B5/B8/B38/B39/B40/B41**.
B7 и B20 исключены после повторённых RF-сбоев на исследованном экземпляре.
Существующие настройки modem/LAN/Wi-Fi/APN при штатной миграции defaults не сбрасываются.

На действующей системе 18 октября 2026 свежая проверка после перезагрузки подтвердила
эту маску, LTE/адрес/маршрут **3/3**, DoH через локальный прокси **3/3** и DNS роутера **3/3**.
За короткое окно проверки новых RF-событий не было. Это наблюдение действующей системы,
а не испытание нового образа или всех диапазонов при регистрации.
[Данные проверки](ufi001c-port/reports/hardware-postboot-20261018.json).

Позднее под 4К-нагрузкой снова наблюдался отказ внешних DNS при запущенном sing-box.
Кандидат включает TCP bootstrap к тому же DNS-серверу, проверку DNS-ответа вместо
одного кода выхода dig и ограниченное восстановление DNS/прокси после трёх сбоев подряд.
Проверяются внешний DoH и оба локальных резолвера; перед восстановлением сохраняется
снимок ресурсов в RAM. Ручная остановка Podkop отменяет восстановление.
Корневая причина исходного обрыва по снимку не установлена; повторная нагрузка на
реальном новом образе остаётся обязательной проверкой.

Новая проверка **CHECK-LTE.cmd** каждый раз создаёт свежий `ufi-postboot-report.tar.gz`.
CONTINUE из live-fix больше не выдаёт прежний запуск за успешное продолжение после reboot.
Причина предыдущей перезагрузки и длительная устойчивость ещё не установлены.

## Podkop

После установки откройте **Службы → Podkop → Секции**, вставьте свою прокси-ссылку,
сохраните и запустите Podkop. Прокси для защищённого DNS оставьте **Автоматически**.
Чужих proxy URL в образе нет. XHTTP и исправления DNS/FakeIP встроены.

До настройки своей секции проверки прокси ожидаемо не пройдут. Прямой внешний DNS
не включается как скрытый резерв. Ошибки удалённого XHTTP/CDN диагностируются отдельно.

## Статус сборки

Это подготовленный **кандидат финальной версии**, не отметка о пройденной аппаратной приёмке.
Готовые boot.img/system.img и переносимые EXE создаёт workflow. Он проверяет Windows-запуск,
хэши исходников и программы, ядро, rootfs и ARM64 XHTTP, затем собирает единый USB-ZIP.
Образ ещё требует реального теста установки со стока, первого запуска и нагрузки.
Поэтому до аппаратной приёмки публикация остаётся **Pre-release**.
